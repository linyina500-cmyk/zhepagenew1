# 本机草稿同步集成审查（2026-09-09）

本次检查了现有导出、页面状态、本地存储和构建配置；未控制用户浏览器、连接真实账号、提交平台草稿或部署。以下测试矩阵是验收建议，不代表已经通过。

## 现有代码与集成点

- `app/hooks/usePosterExport.ts` 的 `renderPage(index, version)` 已返回 PNG Blob；下载和 ZIP 只是消费者。新增 `collectAssets` 复用此方法即可，不需要新截图方案。保留字体等待、语义完整性检查、分页版本一致性检查、渐进挂载全部页和 1 倍原尺寸输出。
- `exporting` 只有 React 状态，两个同一事件周期的调用仍可能并发。所有入口共享 ref 忙碌锁，并在 `finally` 释放；收集草稿失败也要释放。收集期间内容或样式变化必须中止，不可混合版本。完成后素材快照独立，后续编辑不会悄悄替换草稿图片。
- `app/page.tsx` 的封面标题与发布文案不同。两平台各自维护标题、正文和所选账号，首次从海报标题初始化即可。不要为同步改写源正文或让两平台字段互相覆盖。
- 现有 3:4 / 4:5 / 9:16 是产品预设，不是平台接受条件证据。界面可建议适配尺寸；除已核实的硬性限制外不应禁止提交，不自动裁切、不静默删页。
- 工作区已经写入 `localStorage`，并有容量失败分支。新草稿图片不要再编码为 Base64 写入该记录；使用独立 IndexedDB 事务保存元数据和 Blob，容量错误保留上一份完整草稿。删除草稿应同时删除独占素材和撤销缩略图 URL。

## 本机助手的边界

父任务已决定本机 Node 助手：小红书账号使用独立 Playwright profile，公众号使用官方 API，secret 仅在进程内存。此前扩展方案的主要优点是复用当前登录态，但同一浏览器配置下的多个标签页并不天然隔离账号；独立 profile 更适合本任务多账号要求。

1. 助手仅监听 `127.0.0.1`，同时验证精确 Host、Origin、随机会话令牌与请求结构。不能把 CORS 作为鉴权；拒绝 `null` / 未知 Origin、任意远程来源及不受限的动态目标 URL。平台域名、允许动作和草稿接口应在助手中固定。
2. 配对令牌和公众号 secret 不写网页持久存储、不写日志、不进入云端，不回传 secret。小红书的 profile 目录包含会话凭证，须位于非共享设备目录；删除账号明确处理对应 profile。
3. 账号昵称只是展示信息。提交前从会话或平台返回重新验证实际账号标识；选定账号与当前会话不一致即停止该账号任务。
4. 一个提交绑定草稿 revision、图片顺序、账号和请求 ID。只有平台草稿 ID / 可重新读取的保存证据匹配该请求，才显示“已保存平台草稿”。已接收任务、上传完成、已填表都不能替代保存证据。网络中断后状态应为“待核实”，避免直接自动重试造成重复草稿。
5. 两平台、多账号逐项显示结果；一项失败不覆盖其他项成功。不提供发布能力；全部素材校验通过后才开始单账号提交，避免部分图片遗漏而报成功。
6. 本地助手不同于无需权限的普通网页请求。Chrome 的 Local Network Access 覆盖公网网页访问 loopback，并可能请求用户授予本地网络访问；本次本地网页接本地助手应独立验证，不以云端网页连接成功作默认假设。[Chrome 官方说明](https://developer.chrome.com/blog/local-network-access)

如果后续改为扩展：仅允许明确网站来源、运行时核验 sender / 动作 / 数据；Chrome 消息为 JSON 序列化，不应直接假设可传 Blob。扩展数据避免 `storage.sync`，其会通过 Chrome Sync 同步；需要限制内容脚本对存储的访问。[消息与校验](https://developer.chrome.com/docs/extensions/develop/concepts/messaging)、[来源清单](https://developer.chrome.com/docs/extensions/reference/manifest/externally-connectable)、[存储官方说明](https://developer.chrome.com/docs/extensions/reference/api/storage)

## 隐私表述和部署

“草稿在本机保存，提交时直接发往所选平台”是可实现的边界。当前文章导入和远程图片仍使用 `/api/import`、`/api/image`，不可承诺整个现有应用永不访问服务器。

`.github/workflows/verify.yml` 仅运行检查和上传测试产物，没有部署步骤；但 README 明确存在 Cloudflare Git 集成，它独立于 Actions。当前禁止正式部署，最稳妥的是只完成本地改动与检查，不向已连接部署的分支推送。部署控制台规则未在此次只读检查中验证。

## 验收矩阵

| 场景 | 必须确认的结果 |
| --- | --- |
| 导出与草稿同时点击 | 仅一个素材生成任务；完成 / 失败后都可再次操作 |
| 收集中编辑、换色、换尺寸 | 中止本次收集；不混合两个版本的图片 |
| 独立封面、首图正文、超过 4 页 | 顺序及总数正确，输出像素尺寸保持原样 |
| 本机保存、刷新、恢复、删除 | 文案、账号选择、素材顺序与内容一致；删除后无遗留可读草稿 |
| IndexedDB 配额不足 / 事务失败 | 提示保存失败，旧草稿仍完整，不显示已保存 |
| 替换 / 添加 / 删除 / 重排图片 | 类型与实际尺寸可读取，顺序稳定，不裁切；单张替换不会误删其他素材 |
| 两平台编辑与多账号勾选 | 两平台字段互不覆盖；只提交勾选且验证通过的账号 |
| 账号过期或实际账号变更 | 停止对应任务并提示重新登录，不提交到另一账号 |
| 原点伪造、缺令牌、Host 异常 | 助手拒绝，既不泄露账号列表也不创建草稿 |
| 尺寸与图片数量提示 | 建议尺寸可继续；核实的硬性限制明确定位到图片或字段 |
| 一账号成功、另一失败 | 每项结果保留，成功项有可核验平台回执 |
| 平台已保存后响应丢失 | 标记待核实；重新查询或用户核实后再允许可能重复的重试 |
| 对话框键盘及手机 | native dialog 焦点隔离、Esc 关闭、返回触发按钮；底部操作可见且图片列表不撑破页面 |
| 网络与日志审查 | 未提交前标题、文案、图片不发第三方；日志无正文、secret、cookie；不调用发布接口 |
| 原有导出回归 | 单页 PNG 和 ZIP 保持命名、内容及尺寸，失败消息和可继续编辑行为保持 |
